\title{Name or Value? Cue Conflict Reveals When Chain of Thought Overrides Lexical Priors}

\author{Anonymous ACL submission}

\begin{abstract}
Variable names that contradict a program's behavior degrade the accuracy of language models,
but a drop in accuracy does not indicate where inside the model the name interferes.
Interpretability studies of multi-step arithmetic find that intermediate values are computed
during chain-of-thought (CoT) generation; in those tasks, however, the name of a variable and
its computed value never disagree. We introduce a cue-conflict version of such a task, in which
the same problem is presented with congruent, neutral, and incongruent variable names, and
evaluate \NUM{n-models} models with three sets of few-shot examples, \NUM{n-models-all-levels}
of them on all five difficulty levels.
Without CoT, the models use the value denoted by the name: a congruent name raises accuracy by
up to \NUM{facilitationmax} points, and an incongruent name is produced as the answer up to
\NUM{lureexcessmax} points above chance. With CoT, we observe no effect of the name's value at
any level, with one exception. Linear probes indicate that the lure
value is decodable at the name's own tokens and is absent at the step where the chain writes the
variable's value, and activation patching localizes the no-CoT effect to the early layers at the
equation that defines the name. Whether the chain states the value does not predict the size of
the effect.
\end{abstract}

\section{Introduction}

Consider a short arithmetic problem written with named variables:
\begin{center}
\texttt{pen=1 + cup, \quad cup=2 + 3; \quad pen=?}
\end{center}
The answer is 6. We then rename the second variable to the word \texttt{two}:
\begin{center}
\texttt{pen=1 + \textcolor{inc}{two}, \quad \textcolor{inc}{two}=2 + 3; \quad pen=?}
\end{center}
The arithmetic is unchanged and the answer is still 6, but the name of the variable now
denotes 2, while the variable itself holds the value 5. We refer to 2 as the \emph{lure value}
of the name and to 5 as its \emph{true value}. If a model answers 2, or uses 2 in a later step,
the meaning of the name has reached the computation.

Placing two cues in conflict in this way is the design of the Stroop task \cite{stroop1935}
and of the shape--texture experiments on vision models \cite{geirhos2019texture}. We apply this
design to multi-step arithmetic with variable assignments.

\paragraph{Motivation.} Names that contradict the surrounding code degrade model performance
\cite{le2025names,lam2025codecrash,le2026obfuscated}, but such results do not indicate
\emph{where} the name interferes: a drop in accuracy is consistent with a corrupted input, a
corrupted computation, or a correct computation misread at the output. \citet{kudo2026faithful} show, with linear probes and activation patching on such arithmetic,
that each variable's value becomes linearly decodable only as the CoT writes it, but their
variable names are single letters, so a decoded value of 5 can only originate from the
computation. Our incongruent names supply a competing value, so that a probe's output indicates which
source the representation holds.

We construct matched sets of problems: the same arithmetic rendered in the naming conditions of
Table~\ref{tab:conditions} at the five difficulty levels of Table~\ref{tab:levels}, solved with
and without a written chain of thought, on \NUM{n-models} models at level~3 and on
\NUM{n-models-all-levels} of them at every level. Without CoT, the models use
the value denoted by the name: a congruent name adds up to \NUM{facilitationmax} points of
accuracy, and an incongruent name is produced as the answer up to \NUM{lureexcessmax} points
above chance. With CoT, we observe no effect of the name's value at any level, with one
exception among the models we test. Probes indicate that the lure value is decodable at the
name's own tokens and is absent at the step that writes the variable's value.


\section{Setup}

\paragraph{Task.} We reuse the problems, difficulty levels and prompt format of
\citet{kudo2026faithful}. A problem is a list of equations over the digits $0$--$9$ with $+$ and
$-$, ending in a query, and every variable's value is itself a single digit. Three worked
examples of the same level precede each problem, and Table~\ref{tab:levels} gives one problem
per level. Level~3 is our main level.

\paragraph{Naming conditions.} Each problem is generated once and rendered in the conditions of
Table~\ref{tab:conditions}, where arithmetic, operators and digits are identical across a set
and only names differ. In the \emph{congruent} and \emph{incongruent} conditions, exactly one
variable, the \emph{target}, is named by a number word, denoting the target's true value in the
former case and a different value, the \emph{lure value}, in the latter. The target is either
the queried or the intermediate variable, and we report the two cases separately, since they are
different manipulations.

\paragraph{Generation rules.} Only one variable per problem carries a number word, and the lure
value differs from every variable's value and from every digit in the problem, so that a lure
answer cannot be correct for another reason. Names are single tokens in every context of the
template under each model's tokenizer, so twins have the same length and the same token
positions (Appendix~A). The \emph{irrelevant lure} condition places the number word on a distractor.

\paragraph{Regimes.} In the \emph{chain-of-thought} regime, the model writes the worked steps
shown in Table~\ref{tab:levels} and then the answer. In the \emph{direct} regime, it writes only
\texttt{pen=6}. Our main comparison is between these two regimes.

\paragraph{Demonstration sets.} The choice of the three worked examples affected accuracy
more than any naming condition. Every behavioral result is therefore
computed for three fixed demonstration sets and reported as their mean, and we count an effect
as reliable only when its sign is the same in all three sets and a cluster bootstrap over
matched problems excludes zero.

\paragraph{Probes.} A linear probe reads a chosen variable's value from the residual stream,
one probe per position, layer and seed, following \citeauthor{kudo2026faithful}. Probes are
trained on neutral problems only, so that they never observe a number word in a name slot. Each
is paired with a control probe trained on labels that are a fixed random function of the
variable's \emph{name} \cite{hewitt2019control}; where the control also scores highly, the probe
is reading the identity of the name rather than a value.

\paragraph{Patching.} To test whether the name causes a behavior, we replace the activations
at its tokens with those of the matched twin and read the output again \cite{zhang2024patching}.
Two controls accompany every intervention: replacing one neutral word with another bounds the
damage of any replacement, and replacing one lure with another indicates whether the answer
follows the name.

\paragraph{Replication.} On the letter condition, per-token probes trained on letters reproduce
the positions reported by \citeauthor{kudo2026faithful} for Llama-3.2-3B: the queried variable
becomes decodable at equation \NUM{replication-eq-v1} of the chain and the intermediate variable
at equation \NUM{replication-eq-v2}, as in their Table~3.

\paragraph{Behavior.} Table~\ref{tab:behavior} reports accuracy and the pre-registered
contrasts for each model and regime, averaged over three demonstration sets. Without CoT, the
models use the value denoted by the name. A congruent name on the queried variable raises the
accuracy of Llama-3.1-8B by \NUM{facilitationllama318bdirectv1} points at level 3 and by up to
\NUM{facilitationmax} points at level 5, and an incongruent name is answered
\NUM{lure_excessllama318bdirectv1} points above chance at level 3 and \NUM{lureexcessmax}
points at level 5, where accuracy is near the floor (\NUM{lureexcessmax-lo} to
\NUM{lureexcessmax-hi} points across the three demonstration sets). With CoT, these contrasts are
absent. An equivalence test with a margin of \NUM{eq-delta} points finds
\NUM{eq-cot-equivalent} of \NUM{eq-cot-cells} CoT cells equivalent to zero, against
\NUM{eq-direct-effect} of \NUM{eq-direct-cells} direct cells in which an effect is present. The
one exception is the smallest model, \NUM{eq-exc-model}, whose CoT solves
\NUM{eq-exc-neutral-acc}\% of level-\NUM{eq-exc-level} problems with word names and
\NUM{eq-exc-letter-acc}\% with letters. There, a lure on the \NUM{eq-exc-role} variable adds
\NUM{eq-exc-mean} points [\NUM{eq-exc-lo}, \NUM{eq-exc-hi}].

\paragraph{Does the written value explain the effect of CoT?} A natural explanation is that the
chain states each variable's value, and that the stated value replaces the value the name
denotes. We split the incongruent instances by whether the model's own chain stated the target's
true value, and compare each half with the matched neutral twin under the same split. The raw
lure rate differs considerably between the halves, but so does the rate at which the twin
produces that digit, since a model whose chain has broken down produces an arbitrary digit.
After subtracting this baseline, the excess is \NUM{vw-excess-wrote} points over
\NUM{vw-cells-wrote} cells in which the value was written and \NUM{vw-excess-not} over
\NUM{vw-cells-not} in which it was not, so writing the value as text does not account for the
effect. The exception survives the control: \NUM{eq-exc-model} is lured \NUM{vw-olmo-excess}
points [\NUM{vw-olmo-lo}, \NUM{vw-olmo-hi}] on the \NUM{vw-olmo-n} instances in which its chain
wrote the correct value, and injecting the misleading name into a neutral run of it, with a
correct chain force-decoded, moves the answer to the lure in \NUM{exc-inject} of pairs at
layer~\NUM{exc-inject-layer}, against \NUM{exc-ctlword} for the word control at that layer and
\NUM{inject-cot-max} for every other model.

What does line up with the effect is whether the value is \emph{represented} at that step.
Across the \NUM{vs-cells} (model, target) cells for which we have probes, the
\NUM{vs-decodable} whose value is decodable where the chain writes it (accuracy $\geq$
\NUM{vs-decodable-min}) have a lure excess within \NUM{vs-decodable-maxexcess} points of zero,
and the one whose value is not (accuracy \NUM{vs-undecodable-acc}) is the exception. On this
evidence, writing the token is not sufficient: the model must hold the value there.

\paragraph{Word class.} One effect is not removed by CoT. At level 4, a number word on the

(\NUM{wordclass-cost-L4-lo}--\NUM{wordclass-cost-L4-hi} across demonstration sets) whether or not

\section{Related Work}

\citet{kudo2026faithful} established when sub-answers are computed during CoT on clean
arithmetic, and we add a cue conflict to that setting. Two studies apply the Stroop design to language models
\cite{wang2026stroop,hu2026conflict}, but both measure a single next token, without a chain of
thought. Faithfulness has been measured externally by perturbing prompts, chains, or parameters
\cite{turpin2023unfaithful,lanham2023measuring,chen2025reasoning,tutek2025unlearning}; we measure
it internally under a cue whose two values are known. Since small models can
copy the trailing number of the chain \cite{liu2026readout} and an output prior can override a
correct chain \cite{prabhakar2024deciphering}, we report a positional-copy control
(Appendix~B). Misleading identifiers degrade performance on real code
\cite{le2026obfuscated,le2025names,lam2025codecrash}; our synthetic task allows the effect to be
localized.

\section{Conclusion}

We introduced a cue-conflict arithmetic task to ask where a misleading variable name interferes.
Without CoT, the value it denotes is used as the answer, and patching localizes this to the
early layers at the equation defining the name. With CoT, we observe no effect at any level
except in one of \NUM{n-models} models, where the name still moves the answer through a correct
chain. The effect tracks whether the model represents the value at the step
that writes it. Whether the chain states the value does not predict it.

\section*{Limitations}

The task is synthetic arithmetic with short chains, so the results need not transfer to real
code, which is the motivation for the task rather than a finding. The models are at most 12B
parameters, and within-family comparisons indicate the direction of a trend only. The lures are
English number words; digit-bearing names such as \texttt{x2}, other languages, and optimized
lures remain future work. Linear probes can miss information that is encoded nonlinearly; the
patching experiments address this in part, but hidden states carry mixed information and
patching cannot exclude side effects, which is why we report two control patches. Finally, the
CoT format writes the name beside the computed value at every step, which may itself assist
recovery; the direct regime bounds this effect from the other side.

\section{Tokenizer checks}
Our pre-CoT probe maxima on the letter condition, \NUM{replication-pre-v1} and
\NUM{replication-pre-v2}, exceed the 17.8 and 33.2 that \citet{kudo2026faithful} report for the
same model, while the positions agree; we attribute the difference to probe training details.

Rule~4 is decided per model, not by eye. For each model we tokenize every candidate name in the
five contexts of the template (line start, after a comma, after each operator, before the
separator) and keep only words that are a single token in all five with no merging into a
neighbour. For the Llama~3 tokenizer, all ten number words pass and 95 of 112 neutral candidates
pass; the lists are released with the code. The Gemma and OLMo models were run on the same
lists, and the run-time guard confirmed single-token names and identical positions for them. Binary operators carry a space on each side because
\texttt{-} otherwise merges with a following word (\texttt{1-two} tokenizes as \texttt{1},
\texttt{-two}), which would break the alignment between twins. With the released lists, every
instance of a condition tokenizes to the same length with the same position indices, and the
runner excludes and counts any instance that does not; no instance was excluded in any run
reported here.

\paragraph{Positional-copy control.} \citet{liu2026readout} report that small models copy
whichever number stands in the trailing slot of the chain. Pooling the \NUM{copy-n-err} CoT lure

immediately preceding the answer in the model's own chain is the lure in \NUM{copy-lure-frac} of

copying does not account for the CoT lure errors that remain.

rate, lure mass and margin, alongside the accuracy of a control probe trained on labels that are
a deterministic random function of the variable's name \cite{hewitt2019control}. Selectivity is
the difference. The query position is the one cell where a high lure rate coincides with control
