\title{Name or Value? Cue Conflict Reveals When Chain of Thought Overrides Lexical Priors}

\author{Anonymous ACL submission}

\begin{abstract}
Variable names that contradict a program's behavior degrade the accuracy of language models,
but a drop in accuracy does not indicate where inside the model the name interferes.
Interpretability studies of multi-step arithmetic find that intermediate values are computed
during chain-of-thought (CoT) generation; in those tasks, however, the name of a variable and
its computed value never disagree. We introduce a cue-conflict version of such a task, in which
the same problem is presented with congruent, neutral, and incongruent variable names, and
evaluate \NUM{n-models} models with three sets of few-shot examples, \NUM{n-models-all-levels}
of them on all five difficulty levels.
Without CoT, the models use the value denoted by the name: a congruent name raises accuracy by
up to \NUM{facilitationmax} points, and an incongruent name is produced as the answer up to
\NUM{lureexcessmax} points above chance. With CoT, we observe no effect of the name's value at
any level, with one exception. Linear probes indicate that the lure
value is decodable at the name's own tokens and is absent at the step where the chain writes the
variable's value, and activation patching localizes the no-CoT effect to the early layers at the
equation that defines the name. Whether the chain states the value does not predict the size of
the effect.
\end{abstract}

\section{Introduction}

Consider a short arithmetic problem written with named variables:
\begin{center}
\texttt{pen=1 + cup, \quad cup=2 + 3; \quad pen=?}
\end{center}
The answer is 6. We then rename the second variable to the word \texttt{two}:
\begin{center}
\texttt{pen=1 + \textcolor{inc}{two}, \quad \textcolor{inc}{two}=2 + 3; \quad pen=?}
\end{center}
The arithmetic is unchanged and the answer is still 6, but the name of the variable now
denotes 2, while the variable itself holds the value 5. We refer to 2 as the \emph{lure value}
of the name and to 5 as its \emph{true value}. If a model answers 2, or uses 2 in a later step,
the meaning of the name has reached the computation.

Placing two cues in conflict in this way is the design of the Stroop task \cite{stroop1935}
and of the shape--texture experiments on vision models \cite{geirhos2019texture}. We apply this
design to multi-step arithmetic with variable assignments.

\paragraph{Motivation.} Names that contradict the surrounding code degrade model performance
\cite{le2025names,lam2025codecrash,le2026obfuscated}, but such results do not indicate
\emph{where} the name interferes: a drop in accuracy is consistent with a corrupted input, a
corrupted computation, or a correct computation misread at the output. \citet{kudo2026faithful}
show, with linear probes and patching on such arithmetic, that each variable's value becomes
decodable only as the CoT writes it; their variable names are single letters, so a decoded 5 can
only come from the computation. Our incongruent names supply a competing value, so a probe's
output indicates which source the state holds.

We construct matched sets of problems: the same arithmetic rendered in the naming conditions of
Table~\ref{tab:conditions} at the five difficulty levels of Table~\ref{tab:levels}, solved with
and without a written chain of thought, on \NUM{n-models} models at level~3 and on
\NUM{n-models-all-levels} of them at every level. Without CoT, the models use
the value denoted by the name: a congruent name adds up to \NUM{facilitationmax} points of
accuracy, and an incongruent name is produced as the answer up to \NUM{lureexcessmax} points
above chance. With CoT, we observe no effect of the name's value at any level, with one
exception among the models we test. Probes indicate that the lure value is decodable at the
name's own tokens and is absent at the step that writes the variable's value.


\section{Setup}

\paragraph{What we take from \citet{kudo2026faithful}.} This study is built on theirs, and we
state the borrowing explicitly. Taken unchanged: the arithmetic task and its five levels
(their Table~1), the single-digit constraint, the three fixed same-level worked examples, the
probe recipe (a 10-way digit classifier on the residual stream, SGD at $10^{-3}$ for 10{,}000
full-batch epochs, one probe per token and layer), the quantities $t^{*}$,
$t^{*}_{\text{eq}}$, $\mathrm{Acc}^{\prec\mathrm{CoT}}$, $\mathrm{Acc}^{\succ\mathrm{CoT}}$ with
$\tau=0.9$, the span-by-layer-window patching design, and two of their models.
Figures~\ref{fig:heat} and~\ref{fig:kudo3} follow the layout of their Figures~2 and~3. Ours is
the cue conflict: the naming conditions, the matched twins and the rules that keep a lure from
being correct for another reason, the matched-twin baselines behind every number here, the
demonstration-seed claim rule and the equivalence bounds. We reimplemented their task and probes
from the paper rather than running their public code; no code is shared.

\paragraph{Task.} A problem is a list of equations over the digits $0$--$9$ with $+$ and $-$,
ending in a query, and every variable's value is itself a single digit. Three worked examples of
the same level precede each problem; Table~\ref{tab:levels} gives one per level. Level~3 is our
main level.

\paragraph{Naming conditions.} Each problem is generated once and rendered in the conditions of
Table~\ref{tab:conditions}, where arithmetic, operators and digits are identical across a set
and only names differ. In the \emph{congruent} and \emph{incongruent} conditions, exactly one
variable, the \emph{target}, is named by a number word, denoting the target's true value in the
former case and a different value, the \emph{lure value}, in the latter. The target is either
the queried or the intermediate variable, and we report the two cases separately, since they are
different manipulations.

\paragraph{Generation rules.} One variable per problem carries a number word, and the lure value
differs from every variable's value and every digit in the problem, so a lure answer cannot be
correct for another reason. Names are single tokens in every template context under each
tokenizer, so twins share length and token positions (Appendix~A). The \emph{irrelevant lure}
condition puts the number word on a distractor.

\paragraph{Regimes.} In the \emph{chain-of-thought} regime, the model writes the worked steps
shown in Table~\ref{tab:levels} and then the answer. In the \emph{direct} regime, it writes only
\texttt{pen=6}. Our main comparison is between these two regimes.

\paragraph{Demonstration sets.} The choice of the three worked examples affected accuracy
more than any naming condition. Every behavioral result is therefore
computed for three fixed demonstration sets and reported as their mean, and we count an effect
as reliable only when its sign is the same in all three sets and a cluster bootstrap over
matched problems excludes zero.

\paragraph{Probes.} A linear probe reads a chosen variable's value from the residual stream,
one probe per position, layer and seed, with \citeauthor{kudo2026faithful}'s recipe and
hyperparameters. Probes are
trained on neutral problems only, so that they never observe a number word in a name slot. Each
is paired with a control probe trained on labels that are a fixed random function of the
variable's \emph{name} \cite{hewitt2019control}; where the control also scores highly, the probe
is reading the identity of the name rather than a value.

\paragraph{Patching.} To test whether the name causes a behavior we replace the activations at
its tokens with the matched twin's and read the output again \cite{zhang2024patching}. Two
controls accompany every intervention: one neutral word for another bounds the damage of any
replacement, and one lure for another shows whether the answer follows the name.

\paragraph{Does the written value explain the effect of CoT?} A natural explanation is that the
chain states each variable's value, and that the stated value replaces the value the name
denotes. We split the incongruent instances by whether the model's own chain stated the target's
true value, and compare each half with the matched neutral twin under the same split. The raw
lure rate differs between the halves, but so does the rate at which the twin produces that
digit, since a broken chain ends in an arbitrary digit.
After subtracting this baseline, the excess is \NUM{vw-excess-wrote} points over
\NUM{vw-cells-wrote} cells in which the value was written and \NUM{vw-excess-not} over
\NUM{vw-cells-not} in which it was not, so writing the value as text does not account for the
effect. The exception survives the control: \NUM{eq-exc-model} is lured \NUM{vw-olmo-excess}
points [\NUM{vw-olmo-lo}, \NUM{vw-olmo-hi}] on the \NUM{vw-olmo-n} instances in which its chain
wrote the correct value, and injecting the misleading name into a neutral run of it, with a
correct chain force-decoded, moves the answer to the lure in \NUM{exc-inject} of pairs at
layer~\NUM{exc-inject-layer} (\NUM{exc-inject-damage} of answers change in total), while the
word control changes \NUM{exc-ctlword} of answers at that layer and injection moves the answer
to the lure in at most \NUM{inject-cot-max} of pairs for every other model.

What does line up with the effect is whether the value is \emph{represented} at that step.
Across the \NUM{vs-cells} (model, target) cells for which we have probes, the
\NUM{vs-decodable} whose value is decodable where the chain writes it (accuracy $\geq$
\NUM{vs-decodable-min}) have a lure excess within \NUM{vs-decodable-maxexcess} points of zero,
and the one whose value is not (accuracy \NUM{vs-undecodable-acc}) is the exception.

\paragraph{Identifier names.} A bare lexical prior is the weakest form of a misleading name, so

is \NUM{ident-direct-lure-lo} to \NUM{ident-direct-lure-hi} points over

\section{Related Work}

\citet{kudo2026faithful} established when sub-answers are computed during CoT on clean
arithmetic, and we add a cue conflict to that setting. Two studies apply the Stroop design to language models
\cite{wang2026stroop,hu2026conflict}, but both measure a single next token, without a chain of
thought. Faithfulness has been measured externally by perturbing prompts, chains, or parameters
\cite{turpin2023unfaithful,lanham2023measuring,chen2025reasoning,tutek2025unlearning}; we measure
it internally under a cue whose two values are known. Since small models can
copy the trailing number of the chain \cite{liu2026readout} and an output prior can override a
correct chain \cite{prabhakar2024deciphering}, we report a positional-copy control
(Appendix~B). Misleading identifiers degrade performance on real code
\cite{le2026obfuscated,le2025names,lam2025codecrash}; our synthetic task allows the effect to be
localized.

\section{Conclusion}

We introduced a cue-conflict arithmetic task to ask where a misleading variable name
interferes. Without CoT its value is used as the answer, and patching localizes this to the
early layers at the equation defining the name. With CoT we observe no effect at any level
except in one of \NUM{n-models} models, whose value is the one of eight probed cells not
decodable where the chain writes it.

\section*{Limitations}

The task is synthetic arithmetic with short chains, so the results need not transfer to real
code, which is the motivation for the task rather than a finding. The models are at most 12B
parameters, and within-family comparisons indicate the direction of a trend only. The lures are
English number words; identifier-style names were tested at level~3 only, and other languages
and optimized lures remain future work. Linear probes can miss information that is encoded nonlinearly; the
patching experiments address this in part, but hidden states carry mixed information and
patching cannot exclude side effects, which is why we report two control patches. The claim
that the effect tracks whether the value is represented holds across the cells we probed, but
the corresponding instance-level regression of a lure error on the probe margin is not
sign-consistent (Appendix~\ref{app:sweeps}), so that link is weaker than the cell-level
pattern suggests. Finally, the
CoT format writes the name beside the computed value at every step, which may itself assist
recovery; the direct regime bounds this effect from the other side.

\section{Tokenizer checks}
Our pre-CoT probe maxima on the letter condition, \NUM{replication-pre-v1} and
\NUM{replication-pre-v2}, exceed the 17.8 and 33.2 that \citet{kudo2026faithful} report for the
same model, while the positions agree; we attribute the difference to probe training details.

Rule~4 is decided per model, not by eye. For each model we tokenize every candidate name in the
five contexts of the template (line start, after a comma, after each operator, before the
separator) and keep only words that are a single token in all five with no merging into a
neighbour. For the Llama~3 tokenizer, all ten number words pass and 95 of 112 neutral candidates
pass; the lists are released with the code. The Gemma and OLMo models were run on the same
lists, and the run-time guard confirmed single-token names and identical positions for them. Binary operators carry a space on each side because
\texttt{-} otherwise merges with a following word (\texttt{1-two} tokenizes as \texttt{1},
\texttt{-two}), which would break the alignment between twins. With the released lists, every
instance of a condition tokenizes to the same length with the same position indices, and the
runner excludes and counts any instance that does not; no instance was excluded in any run
reported here.

\paragraph{Irrelevant lures.} At level 4 a number word on the distractor changes accuracy by at
most \NUM{irr-acc-delta-max} points. Without CoT it is nevertheless answered \NUM{irr-direct-lo}
to \NUM{irr-direct-hi} points above the neutral baseline (\NUM{irr-direct-claimable} of

\paragraph{Mixed-effects check.} Every lure excess we report is a paired per-set difference
summarised by a cluster bootstrap. A bootstrap over matched sets is not a model of the
dependence between the two members of a twin pair, so we refit each level-3 cell as
\texttt{answered\_lure \textasciitilde{} incongruent + C(seed)} with a random intercept per
matched set, on the long form of the same data: one row per set, condition and demonstration
set, with the outcome on both members being the digit the misleading name denotes, so the
neutral member carries the pseudo-lure baseline. The fixed effect on \texttt{incongruent} is
the lure excess in log odds. The fit
cost grows with the number of random effects, so each cell uses a fixed random subsample of
\NUM{mix-cap} matched sets and both procedures are computed on exactly those rows. Of the
\NUM{mix-cells} cells that admit a fit, \NUM{mix-agree} agree with the bootstrap on whether
the effect excludes zero, and \NUM{mix-unfitted} more have no variation in the outcome and are
not fitted. The \NUM{mix-differ-n} disagreements all run the same way: the mixed model's
interval excludes zero where the bootstrap's does not, and all \NUM{mix-differ-neg} of them
are negative, meaning fewer lure answers under the misleading name than under its neutral twin.
In \NUM{mix-lost} of the \NUM{mix-cells} cells does the
mixed model withdraw support for an effect the bootstrap finds, so no claim in the body rests
on the choice of procedure. We keep the bootstrap in the
body because it estimates the quantity in Table~\ref{tab:behavior} on the scale it is
reported.

\paragraph{Instance-level link, and where it fails.} The body argues at the level of cells:
the one cell whose value is not decodable where the chain writes it is the one cell with a
surviving effect. The finer version of that claim is per instance, so we also fit, for each
(model, level, regime, role), a clustered logit of a lure error on the probe's margin
(log $p_{\text{true}} -$ log $p_{\text{lure}}$) at the layer with the best neutral accuracy.
The mechanism predicts a negative coefficient: a state that favours the true value should
produce fewer lure answers. Across \NUM{link-fits} fits, \NUM{link-sig} reach $p < .05$, of
which \NUM{link-neg} are negative and \NUM{link-pos} positive. The predicted direction
dominates but is not uniform, and \NUM{link-pos-topmodel-n} of the exceptions come from a
single model, so we treat the instance-level link as unresolved and rest the claim on the
cell-level pattern.

\paragraph{Positional-copy control.} \citet{liu2026readout} report that small models copy
whichever number stands in the trailing slot of the chain. Pooling the \NUM{copy-n-err} CoT lure
errors at the answer position over every model, level and demonstration set, the number
immediately preceding the answer in the model's own chain is the lure in \NUM{copy-lure-frac} of
them and the target's true value in \NUM{copy-true-frac}. Neither dominates, so positional
copying does not account for the CoT lure errors that remain.

For every (variable, position, layer, seed) we report probe accuracy for the true value, lure
rate, lure mass and margin, alongside the accuracy of a control probe trained on labels that are
a deterministic random function of the variable's name \cite{hewitt2019control}. Selectivity is
the difference. The query position is the one cell where a high lure rate coincides with control
accuracy near~1, which is why it is reported as name identity rather than as a represented

\section{How the model was tuned}
\label{app:kind}

Table~\ref{tab:behavior} varies family and size. It does not vary how a model was produced from
its pretrained weights, so we add a ladder that holds the spine fixed at Llama-3.1-8B-Instruct
and changes only the tuning: the pretrained model, the instruction-tuned model, a single-task
LoRA finetune, a joint finetune over six tasks, a TIES merge of six single-task adapters, and a
reasoning-tuned checkpoint on the same spine. The three LoRA rows are folded into the weights
before evaluation, so every model in the ladder is an ordinary causal LM with the same
tokenizer; the verified word pool, the token positions and the matched sets are therefore
identical down the ladder, and each rung is comparable to the others instance by instance.

panel, so this rung is a reasoning-tuned model with that mode off. A model reasoning at length
would need a chat template and a different token layout, and is outside this comparison.

matches. The localization we report does not depend on the choice.

\section{A chain that writes values without equations}
\label{app:simple}

Our chain restates each equation before substituting into it, as
\citeauthor{kudo2026faithful}'s does. Their Table~6 also reports a format that writes only the
sub-results, \texttt{cup=5, pen=6}. That format is the arithmetic counterpart of a code trace,
which writes a variable's value and never the expression that produced it, so we ran it on the
panel at level 3 with three demonstration sets, with two predictions registered in advance: that
the name would reach the value step, and that the value would still be decodable there, making
any failure one of readout.

Both predictions fail. Llama-3.1-8B writes the lure at the intermediate's value step
\NUM{simple-l8b-v2} points above its twin, inside the equivalence margin; Llama-3.2-3B is at
\NUM{simple-l3b-v2}, but across the three demonstration sets that is
\NUM{simple-l3b-v2-seeds}, so one set carries it. More informative is what the probes say. At
the step that writes the value, the true value is decodable at \NUM{simpleprobe-l8b-simple-v1}
and \NUM{simpleprobe-l8b-simple-v2} for Llama-3.1-8B and at
\NUM{simpleprobe-l3b-simple-v1} and \NUM{simpleprobe-l3b-simple-v2} for Llama-3.2-3B, against
\NUM{simpleprobe-l8b-cot-v1} and \NUM{simpleprobe-l8b-cot-v2} for the same model under the full
chain. Neutral accuracy falls with it, to \NUM{simple-l8b-acc}\% and \NUM{simple-l3b-acc}\%.

Dropping the equations does not leave the computation intact and expose the readout. It degrades
the computation. Whatever a terse trace does to a model reading code, the arithmetic analogue of
that format is a different phenomenon, and we do not treat the two as one.
