Written reasoning makes intermediate calculations visible, but a model can write a wrong value even when the correct value is recoverable from its internal activity. We study this gap by changing variable names in arithmetic problems and Python programs without changing their computations. Each misleading name suggests a specific wrong value. Building on Kudo et al. (2026), we find that writing arithmetic calculations reduces errors in several conditions, yet a correct calculation can still precede a wrong final answer. In code, misleading names produce frequent wrong intermediate writes when the worked examples list values alone. On those actual errors, a separately trained predictor recovers the correct digit with 95.5–99.7% accuracy immediately before the wrong digit is written. Examples showing the source operation alongside its result sharply reduce errors and increase correct writes. Length-matched text in the examples leaves large errors, and numeric elaboration helps partly. Correct-value recovery therefore does not certify a correct written step, and the content of demonstrated steps matters for reliability.
